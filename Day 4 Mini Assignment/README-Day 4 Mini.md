## Files

- `customer_dataset_lab_cleaned.csv` — cleaned dataset generated by the Python script.

## What the program does

### 1. Profile

The program reads the raw CSV and checks:

- dataset column types using `df.info()`
- percentage of missing values in every field
- number of duplicate `customer_id` records

Profiling happens **before cleaning** so that data-quality problems are measured before anything is changed or deleted.

### 2. Clean

The code performs three documented cleaning decisions:

1. **Duplicate customer IDs** — keeps the last row.
   - Assumption: later records supersede earlier records.
   - The number of removed records is printed.

2. **Email formatting** — removes leading/trailing spaces and converts emails to lowercase.
   - Assumption: case and extra spaces are formatting differences, not different email addresses.
   - The number of changed email records is printed.

3. **Negative monthly spend** — counts negative values first and then clips them to zero.
   - Assumption: negative spend is invalid for this exercise.
   - Counting the affected rows before changing them prevents the source-data defect from being silently hidden.

### 3. Classify

Every field is classified using three properties:

- **Structure** — whether the field is structured data.
- **Sensitivity** — internal, personal or confidential.
- **Scale** — nominal, ordinal, discrete, continuous, or continuous/time.

Examples:

- `customer_id` → structured, internal, nominal
- `email` → structured, personal, nominal
- `monthly_spend` → structured, confidential, continuous
- `plan_tier` → structured, internal, ordinal
- `num_support_tickets` → structured, internal, discrete
- `satisfaction_score` → structured, confidential, ordinal

## How to run

Keep the CSV and Python file in the same folder and run:

```bash
python profile_clean_classify_lab.py
```

The program will read:

```text
customer_dataset_lab.csv
```

and create:

```text
customer_dataset_lab_cleaned.csv
```

## Short assignment note

I first profiled the raw dataset before cleaning so that missing values and duplicate records were visible before any changes were made. I then removed duplicate customer IDs using the explicit assumption that later records supersede earlier records, standardized email formatting, and counted negative monthly-spend values before clipping them to zero. Finally, I classified every field by structure, sensitivity and measurement scale. This exercise showed why storage type alone is not enough to understand a field and why cleaning decisions should always be documented with their assumptions and affected-record counts.

## Important lesson

A cleaning operation can hide a real source-system defect if it is applied silently. For example, changing negative spend to zero may make the data look valid, so the code first records how many negative values were present before making that change.
